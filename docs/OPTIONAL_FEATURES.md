# 启动、自动连接与实验语音

golf.7／通用版保留已有三个独立开关，默认关闭；覆盖Golf旧版不重置已有选项。另增加默认开启的“热点异常自动恢复（旧系统）”，只处理已开启但缺少接口的API17–22热点，见RELIABILITY_PERFORMANCE.md。

| 开关 | 开启后的行为 | 对流畅度的判断 |
| --- | --- | --- |
| 开机打开应用 | 收到系统开机广播后打开首页 | 仅开机时加载应用；不增加连接后的解码任务 |
| 打开应用后自动连接 | 最多等待90秒；蓝牙、热点、保存的手机就绪后发起一次连接 | 等待期间每2秒检查，连接后停止；预计稳态影响很小 |
| Siri／麦克风（实验） | 下次连接宣告语音输入；仅手机请求通话/Siri流时采集、加密上传 | 会增加录音与上传负担；实际车机影响待测 |

这些性能判断来自实现路径，不是实测CPU占用或帧率结果。启用开关本身不会持续录音；语音处理仍在iPhone侧。车机采用旧系统PCM路径，不安装识别模型。语音的工作量通常小于视频解码，但音频驱动、回声处理和边录边播放仍可能影响这台老车机。

自动连接不代替用户开启明确关闭的热点；异常恢复只处理已开启却缺少接口的旧系统AP，也不控制车机蓝牙芯片或车身系统。真实冷启动和休眠唤醒不同；厂家可能屏蔽第三方自启。手动断开、手动开始、未保存的热点修改会取消本次自动等待；返回首页不会立刻自动重连。等待超时后可手动连接，下次重新打开应用或关闭再开启自动连接开关可开始新的等待。

麦克风改动包括API17录音构造方式、实际录音状态检查、语音源不支持时有限回退普通MIC、上行绑定现有CarPlay网络接口、旧系统语音不宣告Opus。断线和结束语音时停止录音；已经结束的流和关闭的录音对象不能再次启动。读取或启动失败只关闭语音上行，不抛出错误中断视频。

内置麦克风可能只接到车机的专用蓝牙通话模块，Android应用未必能录到声音。能创建录音对象也不等于真实收音正常；需在车机上检查说话电平、Siri识别与通话回声。标准Android语音键在投屏窗口中请求Siri，车机固件是否把方向盘信号交给应用仍需验证；也可使用CarPlay屏幕上的Siri入口。

2026-10-06：用户确认golf.5在本车Siri与麦克风正常，其他基础功能未发现异常；没有提供真实冷启动、通话回声或语音期间CPU／帧率比较，不能把这些当作已验收。本次golf.6保留该音视频路径，增加原生画质及按键转发，见NATIVE_DISPLAY_KEYS.md。

## 原版主线与当前适配版

查阅2026-10-05的[主线0.2.12发布说明](https://github.com/shihabal3amri/DiPlay/blob/main/docs/RELEASE-NOTES-0.2.12.md)，主线最低Android9，不能原样安装到已检测为Android4.2.2的这台车机。

主线近期新增/扩展主要包括：同一现有Wi-Fi网络连接、分屏/桌面地图卡片、独立系统栏与多指菜单、日夜模式与图像参数调整、更宽的分辨率范围、方向盘/旋钮和仪表导航扩展，以及连接恢复和故障报告改进。厂商车身/HUD/仪表集成不适用于当前选择。

golf.5继续基于Legacy0.2.7，保留已连通的无线、触摸、播放音频和golf.4画质/全屏处理。这次只恢复可选启动与语音，没有移植主线分屏、图像滤镜或厂商车辆接口。删除的厂商部分保持删除。

## 实车比较

建议先保持三开关关闭确认覆盖后正常；再分别开启自动连接、自启与麦克风。自启需冷启动，自动连接需测试手机不在车内、热点迟开和手动断开。语音先测短Siri请求，再短通话；比较使用时和结束后的地图滑动/音乐。失败后关闭语音并断开重连；导出的golf.5报告可区分没有协商语音、录音源不可用、读取失败或无有效收音。
