# golf.4 显示改进方案与实施计划

用户已确认 golf.3 能连接、基本功能正常，选择新版默认均衡画质（约800x480、30fps），同时保留原画质回退。此计划在当前已隔离的本地改版中直接执行，继续使用原包名与签名。

## 证据与边界

21:31和21:36的报告确认普通MTK AVC解码器正常启动并送显，输入缓冲区1MiB、AVC High profile100/level30；21点的记录没有解码器启动或运行异常。大多数统计接收和送显速率接近，动态画面可达30fps；长会话有一次超过250ms的积压恢复。统计包含静态画面和切换页面，低收帧速率不能独立证明无线丢包。具体拖影原因和新画质的性能仍需实测。

照片中的顶部系统栏遮住CarPlay第一排图标。应用使用的AndroidX Core1.9.0在API20以下选择空的WindowInsetsControllerCompat.Impl，现有hide调用无效，而布局又允许延伸到系统栏下方。应先修正这个已确认的兼容逻辑，再由实机确认车机固件是否允许隐藏。

视频TextureView没有设置变换，视频铺满自身边界，却显式要求透明合成。本轮恢复不透明视频层，降低不必要的合成负担；不保证消除面板响应或固件解码导致的拖影。照片中的返车图标仍为旧厂商标志，替换为本项目生成的普通汽车图标。

## 方案

- 默认均衡：80%画质，在1024x600画布上约820x480，H.264/30fps；流畅档保留60%（614x360）。选择持久保存，重新连接时生效，不重置热点、配对、认证或音频。
- API17–19使用旧式窗口全屏标志；API17/18不使用会吞掉首个触摸的隐藏导航栏方式，API19才能使用沉浸模式。现有恢复焦点处理继续重申全屏。
- 首页增加“画质与显示”。顶部系统栏避让默认关闭；开启时视频与触摸共享同一64dp顶部留空区域，避免隐藏失败时仍遮挡内容。改变此设置需重新连接，避免半途改变会话画布。
- 视频使用不透明TextureView；保留原解码器选择、基础格式和所有协议处理。更新中性汽车图标与报告版本/画质/全屏状态。
