# golf.6 画质与方向盘按键

这台车机的实测投屏区域是1024×600。10月6日10:48会话正在解码820×480视频，所以仍有一次放大。报告头保存的smooth设置用于下次连接；本次实际大小看DisplayDiagnosticSnapshot及当前diplay.log，不能只看偏好值。解码器stride1920／slice1088是缓冲区布局，不是屏幕分辨率。

## 匹配清晰度

首页“画质与显示”选“清晰（匹配屏幕1024×600）”，保存，断开并等连接停止，再开始无线连接。全部保持30帧。更新不强制改动原有画质，均衡与流畅也仍可选。开启64dp顶部避让时按剩余可用区域匹配，实际高度相应降低。

1024×600每帧像素比820×480多约56%，可减少放大造成的模糊，但这不是CPU负载增幅，也不是流畅保证。若地图移动或滑动卡顿明显增加，切回均衡并重新连接；更低负载仍可用流畅。屏幕像素密度与老面板响应造成的观感不能靠提高视频分辨率消除。

## 按键第一版

- 上一首／下一首：收到标准Android媒体键时，每次初始按下发一次CarPlay指令，长按重复与释放不连跳；窗口／广播重复副本去重。
- 一个电话键：短按释放请求Hook Switch接听，长按至少800ms（约1秒）释放请求Drop挂断。长按期间不先发送接听。若固件发送单独ENDCALL键，则按下直接请求Drop。
- 语音键：仍在释放时请求Siri；电话键不映射到Siri。音量、仪表翻页键不重映射。

通话使用上游已有并向iPhone公布的Telephony HID，不依赖车机电话权限、不恢复任何厂商MCU／HUD／ADB接口。HID数组序号1对应Usage0x20 Hook Switch，序号3对应Usage0x26 Drop；并不是直接发送0x20或0x26。[USB HID Usage Tables](https://www.usb.org/sites/default/files/hut1_7.pdf)定义两种通话用途，但不能据此证明本iPhone会如何处理CarPlay中的按下／释放。因此以上是已实现的发送映射，实际接听、挂断必须测试。

原音乐和蓝牙电话能收到方向盘键，只能证明固件的原生通道正常；如果它不向普通应用发Android事件，本次通用转发无法直接接到信号。不得把MCU或CAN未知值猜成通话指令。

## 本车验证

先在投屏里播放iPhone音乐，分别按两次上一首／下一首。来电时短按电话键；接通后长按约1秒并释放。再验证Siri、麦克风、触摸、音乐与断开重连。观察是否每次只执行一次。

若按键仍无反应，返回首页打开“实体按键检测”，分别按上一首、下一首、电话、语音键。检测页只显示／记录事件，不发音乐／电话指令；是否弹出原车界面也请记录。关闭检测页并导出报告。没有任何事件是判断固件输入路径的证据，不能从代码测试推断硬件已修复。

报告追加hardware-keys.log与单独历史，包含source、code、scan、action、repeat、route和queued。queued=true仅表示进入本地发送队列；当前会话日志的pressWritten／releaseWritten才表示消息写出，均不表示iPhone执行成功。日志不录音、不记录按键字符或通话号码。检测页只在打开时捕获，没有后台扫描、录音或按键轮询。

标准媒体注册在连接初始化时进行，恢复前台与音乐状态时重申；没有每帧任务。按键处理只在有事件时执行，新增日常负担很小；清晰档增加视频像素处理才是本次主要性能变量。
